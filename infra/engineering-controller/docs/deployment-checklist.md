# Secure hybrid deployment checklist

**Do not deploy until the controller/worker are hardened and tested.** This is an operator checklist, not evidence of a deployed system.

## 1. Cloud VPS
- Provision Ubuntu 24.04 LTS, >=2 vCPU, >=4 GB RAM, 40 GB disk.
- Enable provider MFA, SSH keys only, automatic security updates, backups and cost alerts.
- Keep PostgreSQL and controller private; never open 5432 or 8080 to the internet.
- Connect VPS to the same Tailscale tailnet as the Ubuntu build PC.
- Restrict inbound SSH to approved management addresses or Tailscale SSH.

## 2. Ubuntu build worker
- Create dedicated non-admin user `neuron-worker`.
- Run builds in isolated ephemeral containers without privileged mode, host Docker socket, personal home-directory mounts, or host SSH credentials.
- Permit only approved outbound destinations; isolate secrets from untrusted code.
- Ensure persistent power and internet, sufficient disk for Android SDK and Gradle.
- Do not grant the coding agent root/sudo or automatic merge privileges.

## 3. GitHub App
Create a GitHub App under Settings → Developer settings → GitHub Apps.
Install only on `gokul-hastrophil/neuron`.
Recommended initial repository permissions:
- Metadata: read (mandatory)
- Issues: read/write (job status comments)
- Contents: read/write (feature branches)
- Pull requests: read/write
- Checks: read (CI status)
Do not request Actions workflow write, Administration, Secrets, or organization-wide permissions.
Store the app private key in a root-readable file on the controller host, mounted read-only to the container with least-privilege access.
Set `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, `GITHUB_APP_PRIVATE_KEY_PATH`.
Installation tokens are short-lived and generated by the controller; never commit or paste tokens.

## 4. OpenAI
Create a project-scoped API key in your OpenAI API platform project.
Set project budget alerts and a hard application-side task budget.
Store the key only in the isolated worker secret store; never in GitHub, prompts, logs or a committed .env file.
Cloud coding runtime integration is **not yet implemented**.

## 5. Approval boundary
- Approve provisioning/purchasing VPS separately.
- Approve installing the GitHub App on the repository.
- Approve enabling worker code execution only after test evidence.
- Keep merge, release, paid purchases and production deployment manual.

## 6. Pre-production acceptance
- Integration tests: database recovery, stale lease, concurrent claim, API auth.
- Sandbox escape and prompt-injection tests.
- CI runs and review required before PR is ready.
- Verify restore from backups.
- Verify audit events, cost ceiling, and kill switch.
